## Range investigation and limits

`sourceLabel` already supports building-prefix ranges when source `streetnumber1` and `streetnumber2` confirm the entire displayed range. A preliminary diagnostic omitted structured fields and appeared to reproduce a parsing bug; adding confirmed synthetic start/end fields showed the existing code correctly accepts an exactly entered range. The suspected parsing fix was withdrawn before changing the module. The actual log probe only records formatted address, first street number and unit, so its missing endpoint cannot be assumed to represent the full provider record.

New `qa/release-range-diagnostic.cjs` uses captured public labels with explicitly synthetic identifiers/coordinates. It verifies bare-number vetoes, conservative rejection when the structured endpoint is not established, fully structured exact-range matching, multiple-identity review and exact Dixon unit distinction. It does not establish official Gosford aliases or actual parcel relationships. No application data module was changed by this investigation.
