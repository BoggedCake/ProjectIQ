# Property data source review — 15 October 2026

## Decision

Do not activate any of the five reviewed repositories as a SitePivot market feed. Two contain only actor advertising, one is an explicitly broken archived scraper, one is an example client whose sold-price field is an **estimate**, and one is an independent API catalogue. None establishes SitePivot's commercial redistribution rights. Prefer a direct licensed Pricefinder API agreement for a future full market adapter; a licensed NSW Property Sales Information (PSI) import is a narrower alternative. Neither is connected or access-tested here.

Bulk NSW land values are a separate contextual source, not a substitute for sale prices or an improved-property appraisal. Its catalogue advertises CC BY 4.0, but the current custodian page requires an access request. Confirm the supplied dataset's licence before ingestion. No unconditional integration-ready feed was established.

## Scope and evidence standard

Read `property-evidence.js`, `api/market/property.js`, `api/_lib/market.js`, the planning-source register and founder authority/testing documents before evaluating sources. Research used GitHub's connector for actual file contents and primary provider/government pages for terms. This is static source/schema review and public-document retrieval only: no actor, scraper, paid API, property-data import or live comparable query was executed; no account, purchase, outbound message or security bypass was attempted. Repository counts below are the public tree at review time, not a complete maintenance audit. Dates advertised by authors are distinguished from verified operational freshness.

## Stronger legitimate sources

### Direct Pricefinder: full-feed candidate, commercially gated

The [official schema](https://api.pricefinder.com.au/v1/swagger.json) is Swagger 2.0 v1.13.1 and describes property, sale, listing, suburb, spatial, AVM and CMA operations with OAuth token flows. It is a contract, not a live data result. [Official data provenance](https://www.pricefinder.com.au/our-data/) states daily Domain/Allhomes listing feeds, government sale/valuation data and third-party enrichment. That does not guarantee every property's freshness or API field completeness. [Official onboarding](https://www.pricefinder.com.au/get-started/) offers custom property API packages; price and SitePivot entitlement are unknown.

The [API terms](https://www.domain.com.au/group/api-terms-and-conditions/) require schedule-approved integration/purpose, authorised users, provider review before live end-user access, security/privacy controls and anti-scraping protections. They restrict third-party display/distribution unless permitted. Paid products default to **12 months unless the schedule says otherwise**; do not adopt the catalogue's minimum-one-month claim. Obtain a concrete approved SitePivot schedule before implementation or expenditure.

### NSW VG sales: authoritative transactions, commercial licence required

The [current custodian page](https://www.nsw.gov.au/housing-and-construction/land-values-nsw/how-to-find-property-sales-information) says sales originate in Notices of Sale and bulk history extends to 1990. Crucially, publicly supplied sales information is **CC BY-NC-ND 4.0**, and a PSI licence is required for commercial use, business sharing or inclusion in products/services. Do not classify the free download as commercially open data. The older [bulk landing page](https://www.valuergeneral.nsw.gov.au/design/bulk_psi_content/bulk_psi) advertises weekly current files but direct retrieval failed; current delivery cadence and access must be confirmed through the [replacement portal](https://valuation.property.nsw.gov.au/embed/propertySalesInformation), not assumed from the legacy page.

The [official format](https://www.nsw.gov.au/sites/default/files/noindex/2024-05/Current_Property_Sales_Data_File_Format_2001_to_Current.pdf) specifies semicolon-delimited records: property/district IDs, address, area/unit, contract/settlement dates, purchase price, zoning, nature of property, strata lot, sale code, interest percentage, dealing number and legal-description records. Owner details are suppressed. Sale counter is unique **within the file**, not a universal transaction ID. The [data dictionary](https://www.nsw.gov.au/sites/default/files/noindex/2024-05/Property_Sales_Data_File_-_Data_Elements_V3.pdf) traces individual fields to the register/Notice of Sale. Beds, baths, dwelling condition, floor area, photography and current asking prices are not supplied in that format. Static document review only; no file downloaded or parser tested. A future licensed import needs staging, identity matching, amendment/deduplication handling, geocoding and a spatial index, with monitoring of source delivery lag. The format PDF's copyright notice is not a licence to the transaction dataset.

### NSW bulk land values: useful context, access still gated

[Data.NSW](https://data.nsw.gov.au/data/dataset/http-www-valuergeneral-nsw-gov-au-land-value-summaries-lv-php) describes monthly ZIP/CSV files by LGA, property data and up to five valuation years, with CC BY 4.0; catalogue last updated 28 April 2025. The [current custodian access page](https://www.nsw.gov.au/housing-and-construction/land-values-nsw/how-to-find-land-values-nsw) requires requesting bulk access to ensure licence compliance. This is a material access qualification, not an anonymous API. No request sent, bulk schema inspected, download tested or new authentication performed. Cost/conditions of the actual delivery remain unconfirmed; importer/storage/attribution would be needed. [Official valuation guidance](https://www.nsw.gov.au/housing-and-construction/land-values-nsw/why-land-values/how-land-valued-nsw) removes building improvements and anchors values to 1 July. Keep land value and valuation date visibly separate from improved-property market value.

## Adapter boundary and appraisal feasibility

Current `api/_lib/market.js` already returns review/empty evidence without `SITEPIVOT_MARKET_ENDPOINT`; retain that behaviour. Its server gateway expects `market-v1` and returns separate current listings, sold comparables, current-property evidence and completed-product comparables. The row validator checks positive numeric price, ID/source and past ISO sold date, but **cannot establish transaction provenance, rights, identity or comparability**. Therefore an upstream adapter must reject estimates, asking-price ranges, undisclosed transactions, partial interests and anomalous/non-comparable sales before mapping. No product change is made by this research.

Recommended future implementation is an original server-side adapter to a directly licensed provider, not copied scraper code. Carry provider transaction/property IDs, actual contract and settlement dates, source URL, retrieval time, price kind, rights/expiry and matching confidence in retained provenance; never expose credentials. Preserve unknown attributes as null. Keep current listing asking prices contextual and use only independently verified transaction prices for sold-derived ranges. NSW PSI alone can supply a defensible transaction shortlist after licensing, but needs lawful dwelling-feature enrichment and human selection for an improved-home appraisal.

An evidence-based indicative appraisal is feasible only once legitimate recent comparable sales are available and the subject's dwelling/land scope is verified. Proposed methodology (not executed): select multiple arm's-length sales of similar type, location, land, size, beds, condition and sale date; disclose included/excluded comps and individual adjustments; produce a dated range with uncertainty and abstain when evidence is insufficient. Treat completed duplex/renovated-product comps as a separate set matched to the proposed product. Unknown condition, views, access, title/strata restrictions, reporting lag and thin markets materially limit accuracy. Do not turn GIS land area, VG land value, suburb averages, listing guides or an actor's `estimatedPrice` into a current market appraisal. `property-evidence.js` correctly keeps cadastral GIS indicative and flags conflicting advertised area; market data must not overwrite that provenance.

## Adapter implementation after source review

The existing market-v1 gateway now accepts an optional propertyProfile only with exact structured address/unit plus matching parcel lot/plan, stable ID, source and real source date. Each field retains its own evidence status and date. Land, internal and building area remain separate; invalid/missing values remain null. Explicit non-sold evidence kinds are rejected from sold arrays. Existing licensed-provider contract remains disabled without credentials/rights; no new feed or comparable dataset was activated. Nine focused regression groups and the existing provider contract passed.
