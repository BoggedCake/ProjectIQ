# Unified SitePivot conversation

Approved specification: founder's 30-section unified conversation brief, 7 October 2026.
Baseline: 752a91d400c0595fec338e06458065d35a7b2d69, sitepivot-concept. Never merge main.

Audit: the current passport has two independent composers. Intake extracts a single project profile and ignores questions; Q&A never applies project intent. Both have independent recognition targets. Speech uses browser synthesis only. The startup property button is bound through bind() and covered by every existing journey. Existing planning, cadastral and commercial calculations remain authoritative.

## Task 1: validated conversation contract
Write and watch A–G regression conversations fail, then implement one normalized interpreter and validated action reducer. Reuse the commercial interpreter. Questions must never manufacture or mutate property evidence. Comparison candidates must not arbitrarily select a pathway. Preserve existing state for pure questions and partial follow-ups. Verify pure tests and existing models.

## Task 2: voice adapters
Write failing provider/client tests, then add server audio route, bounded cache, credential isolation, timeouts and cancellation; client audio cancellation and browser fallback with quality-first voice ranking. Speech remains concise and metadata-free. Verify cancellation, stale callbacks, no overlap, fallback and configuration.

## Task 3: single persistent consumer conversation
Remove duplicate intake DOM. One composer and conversation persist across passport, scope, assessment, roadmap/report. Manual choices remain secondary. Apply validated actions, answer deterministic property questions, present conversational continuation/edit controls. Voice final transcripts use the same submit path. Protect all existing consumer assertions while updating selectors to the unified component. Verify full local suite and browser journey after changes.

## Task 4: deployment and acceptance
Run all model/commercial/async/provider tests, Chromium and mobile WebKit journeys, conversation and voice regressions, live provider QA and deployed founder scenarios for Seaforth/Fairlight. Check console, network, navigation, resets and stale responses. Obtain one fresh independent whole-change review, fix material findings with regression tests, rerun complete suite. Publish only sitepivot-concept. Record external AI/TTS credential requirements honestly.

Shared interfaces: conversation.js uses commercial-engine.js; voice.js uses server /api/voice/speak; index.html uses both modules; QA servers must serve and JSDOM must inject both modules. No independent financial or planning calculations.
